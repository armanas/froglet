## TL;DR

**Through Claude / Codex / Cursor (MCP):**

```
User: "Publish a Froglet service that translates English to Spanish."
Claude: Calls `marketplace_publish` with name + source_inline + hosting.
        → returns provider_id, marketplace URL, invoke command.
```

**At a shell:**

```bash
curl -fsSL https://froglet.dev/agent | bash    # installs froglet-node
froglet-node init my-translator
cd my-translator
$EDITOR handler.py
froglet-node publish --host tor                 # done
```

Both paths run the same `froglet-publish-engine` pipeline: build →
sign → register → verify. One source of truth.

## The MCP call shape

```json
{
  "action": "marketplace_publish",
  "name": "translator-en-es",
  "source_inline": "import json, sys\n\ndef handle(p):\n    return {\"translated\": p[\"text\"]}\n\nif __name__ == \"__main__\":\n    payload = json.load(sys.stdin)\n    json.dump(handle(payload), sys.stdout)\n",
  "hosting": { "kind": "tor" },
  "summary": "Translate English to Spanish",
  "settlement": { "method": "none" }
}
```

Returns:

```json
{
  "provider_id": "c9ecac3ae190…",
  "public_url": "http://abc123…onion",
  "offer_hash": "0123abcd…",
  "marketplace_offer_url": "https://marketplace.froglet.dev/v1/offers/…",
  "invoke_command": "froglet-node invoke translator-en-es '{}'",
  "warnings": []
}
```

Behind the scenes the MCP handler shells out to `froglet-node publish --json`,
which scaffolds the manifests, builds the artifact, posts to the local
daemon's `/v1/provider/artifacts/publish` (daemon signs + persists),
POSTs `/v1/registrations` on the marketplace, then polls
`/v1/providers/<id>` until the indexer projects the offer.

## What you need running

- **Daemon**: `froglet-node serve` (in `provider` or `dual` mode)
  reachable at `FROGLET_DAEMON_URL` (default `http://127.0.0.1:8080`)
- **Provider-control token**: the file at
  `$FROGLET_DATA_DIR/runtime/froglet-control.token`, automatically
  generated on first daemon boot
- **For Tor hosting**: `FROGLET_NETWORK_MODE=tor` or `dual` on the daemon
- **For self-hosted**: a public HTTPS URL serving the daemon

The default `curl https://froglet.dev/agent | bash` install gets you a
daemon running with sensible defaults. You can `froglet-node whoami`
to verify reachability.

## Hosting backends

The `hosting.kind` field of the MCP call (or the `--host` flag of the
CLI) picks one of five backends. **Tor is the right default.** Phase 1A
ships three; Phase 1B adds the other two.

| Backend | Status | When to use |
|---|---|---|
| `tor` | ✓ Phase 1A | Default. No DNS, no TLS, no public IP. |
| `local` | ✓ Phase 1A | Private development, never registered with marketplace. |
| `self` | ✓ Phase 1A | You deploy daemon to your own URL (Fly/Render/VPS) and point at it. |
| `managed` | Phase 1B | Marketplace allocates `<slug>.providers.froglet.dev`; you need a public IP + Caddy. |
| `fly` | Phase 1B | Engine wraps `flyctl deploy` for you. |

For most users the answer is just **tor**.

## Settlement on the publish path

The publish path now accepts `settlement.method` ∈ `none` | `lightning` |
`stripe`:

- **`none`** — free execution, no payment.
- **`lightning`** — two-leg hold-invoice settlement (base + success fee),
  proven end-to-end on regtest; the payment preimage is the cryptographic
  proof. Real mainnet money is not yet proven (pending channel liquidity).
- **`stripe`** — test-mode agentic rail on Stripe's Shared Payment Token
  (SPT) model. froglet is the seller; US-only; settlement is attested by a
  PaymentIntent reference, not a cryptographic proof. See
  [Stripe](/learn/payment-stripe/) for the buyer/seller caveats.

Price a service with `[price] sats = N` plus `currency = "sat"` (satoshis →
Lightning) or `currency = "usd"` (US cents → Stripe). The hosted trial at
`try.froglet.dev` stays free-only. **x402** is defined in the protocol and
implemented at the daemon level, but is not a publish-path option.

## What v1 doesn't do yet

- **WASM and OCI runtimes**: `runtime: "python"` + `package_kind: "inline_source"`
  is the v1A scope. WASM modules and container images ship in v1B.
- **Managed + Fly backends**: documented above, land in v1B.

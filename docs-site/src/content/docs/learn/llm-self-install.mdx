This page is for LLM readers. Human readers should start with
[Quickstart](/learn/quickstart/).

## Prime Rule

There is one maintained automation surface: `froglet-mcp`.

Use the shell only for the setup bootstrap. After the node is running, do not
invent separate CLI flows. Use MCP actions for status, service publication,
invocation, public registration, payment planning, and marketplace operations.

If the user only wants the hosted no-install proof, use
`https://froglet.dev/llms.txt` instead of `froglet-mcp`. If the user already has
a local Froglet node and only needs the MCP stdio server, use:

```bash
npx froglet-mcp
```

## Bootstrap

If the user asks to run Froglet locally and has approved host-shell setup, run:

```bash
curl -fsSL https://froglet.dev/agent | bash
```

Use target overrides only when needed:

```bash
FROGLET_AGENT_TARGET=codex curl -fsSL https://froglet.dev/agent | bash
FROGLET_AGENT_TARGET=manual curl -fsSL https://froglet.dev/agent | bash
```

The bootstrap prints JSON. Read these fields back to the user:

- `provider_url`
- `runtime_url`
- `mcp_config_path`
- `compose_file`
- `next_mcp_actions`

Then restart or point the agent at the printed MCP config path.
The default footprint is docker-backed provider/runtime from published images;
source checkout is contributor mode only.

## First MCP Sequence

After MCP is connected:

1. Call `status`.
2. Call `publish_artifact` with `template: "demo.add"`.
3. Call `list_local_services`.
4. Call `invoke_service` for `demo.add.local` with `{"a":7,"b":5}`.
5. Report the result, service metadata, receipt evidence, and any missing
   proof. Do not claim public reachability or paid settlement yet.
6. Call `plan_use_case` before implementing the user's real workflow.

## Install Planning

If the user asks for options before running setup, call:

```text
action: plan_install
```

If `payment_rail` is omitted, MCP should return `decision_required`. Recommend
`none` for the first install, normal evaluation, and any buyer-facing demo. Paid
rails are operator-only choices unless a managed Froglet surface is handling the
payment backend for the user.
After the profile is confirmed, call `get_install_guide` before executing host
shell commands.

Current payment options:

- `none`
- `lightning-lnd-rest`
- `stripe-test`
- `stripe-live`
- `x402`

Do not ask for live Stripe keys, LND credentials, or wallet/facilitator inputs
until local health and the free demo have passed, and do not ask ordinary buyers
for those inputs at all.

## Public Reachability

Local health is not public reachability. If the user wants to appear in the
marketplace, choose one of these paths:

- **Tor**: zero-cost and NAT-friendly. Use `registration_transport=tor`.
- **Froglet-managed subdomain**: zero-cost clearnet, but requires public
  inbound connectivity. Use `marketplace_domain_claim`, then
  `marketplace_domain_complete`, then `marketplace_register`.
- **Own HTTPS domain**: advanced/operator path. Register only after the
  provider advertises the exact public HTTPS origin.

Reject raw IP and self-signed clearnet marketplace registration. For local dev,
keep the node unregistered.

## Backend Integration

Ask what the user wants to expose and pick the smallest viable path:

- demo
- local script
- HTTP backend
- mounted files
- database helper
- OCI image
- GPU service

Publish one service, invoke it locally, then only expose/register it if the user
explicitly wants public use. For paid services, prove a tiny settlement and the
failure path before claiming the rail works.

## Commands Must Run On The Host

Do not route installation through `invoke_service` or `run_compute`. Froglet
cannot install itself onto a host it is not already controlling. Use the host
shell exposed by Claude Code, Codex, or the user's agent host.

## Fresh-Host Proof

For an isolated no-clone proof:

```bash
curl -fsSL https://raw.githubusercontent.com/armanas/froglet/main/scripts/fresh_host_quickstart_smoke.sh | bash
```

Use `--skip-start` when Docker images are not expected to be pullable in the
current environment but the installer/config path still needs evidence.

## Residual Limits

- Real Lightning needs user-owned LND credentials and liquidity.
- Stripe live needs a fresh human approval and a tiny live payment/refund proof.
- x402 needs wallet/facilitator setup and verify/settle evidence.
- Public HTTPS on a clearnet hostname still needs public inbound connectivity.
- OpenClaw no-clone setup is not complete because the OpenClaw plugin is a
  repo-local folder today.

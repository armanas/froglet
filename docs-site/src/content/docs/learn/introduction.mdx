## Bob has something Alice can use

Bob's lab has a table that matches different names for the same research terms.
Alice needs those matches for her own analysis. She does not need Bob's entire database.

1. **Bob chooses the useful part.** His assistant prepares a separate copy containing only the selected collections and fields.
2. **Bob checks an example.** He sees what is included, what is omitted, and what Alice would receive from a lookup.
3. **Bob approves sharing.** He chooses public access or an invitation and sends Alice the service link. Invitation credentials travel separately.
4. **Alice decides whether it helps.** She or her assistant inspects the description, example, and terms before using the service.

This is the idea behind a **service**: something useful another person can ask
your computer to do. It could look up a record, return a selected dataset, or
run a specific calculation. It does not give someone general access to your computer.

## What you control

- **The material:** selected data or a specific operation, with an example you can review.
- **Access:** public use or invitations; current invitations apply to the provider, not to one individual service.
- **Limits:** the supported input and execution limits for the chosen service type.
- **Availability:** you run the provider and can pause access. Already delivered results cannot be recalled.

The [sharing guide](/learn/share-services/) explains these controls and their limits.
The supported first-use path is **free**. Paid rails have separate setup and
[maturity limits](/learn/payment-rails/).

## The words you will see in the docs

| Term | Plain meaning |
| --- | --- |
| Provider | Bob's Froglet node: the computer making a service available. |
| Requester | Alice's Froglet node: the computer asking to use it. |
| Offer | The description of what a service accepts, returns, and costs. |
| Quote and deal | The proposed terms for one request and the requester's commitment. |
| Receipt | A signed record of the provider's reported outcome and relevant hashes. |

Signed records let people check which key signed a commitment and whether the
record was changed. They do **not** establish a person's legal identity or prove
that a result is correct. Read [Trust & Economics](/learn/economics/) for that boundary.

## What is available today

The current public beta supports guided free sharing with **Codex or Claude Code**
on **Apple Silicon macOS and Linux x86_64/arm64**. The provider's computer must
stay awake and online. See the [release and setup requirements](/learn/share-services/).

For organizations, the direction is to turn agreed sharing rules into a working
service. Froglet does not currently interpret arbitrary legal agreements or
automatically deliver every SLA. [The organization page](/managed/) separates
current controls from that longer-term direction.

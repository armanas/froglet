## Public-key cryptography

A **private key** creates a digital signature. The matching **public key** lets
someone check that signature and detect changes to the signed message.

Signing does not encrypt a message or make it private. A valid signature is
evidence of control of the signing key, not proof of a person's name, honesty,
or the truth of the message.

## secp256k1

Froglet uses the **secp256k1** elliptic curve — the same curve used by Bitcoin, Ethereum, and Nostr. The math works on a curve defined by:

$$y^2 = x^3 + 7 \pmod{p}$$

where $p = 2^{256} - 2^{32} - 977$ is a very large prime number.

A **private key** is a securely generated integer in the curve's valid secret-key range, encoded in 32 bytes. The corresponding **public key** is a point on this curve computed by multiplying the curve's generator point $G$ by the private key $k$:

$$P = k \cdot G$$

This multiplication is easy to compute but practically impossible to reverse — you cannot derive $k$ from $P$. This is the **elliptic curve discrete logarithm problem**.

## BIP340 Schnorr signatures

Froglet uses **BIP340 Schnorr signatures**, with 32-byte x-only public keys and
64-byte signatures. The verification relationship is $sG = R + eP$, subject to
the specification's checks. BIP340 also defines tagged hashes, nonce
derivation, scalar bounds, and point-parity rules. The equation alone is not
an implementation recipe. Use a tested implementation and the
[BIP340 specification and test vectors](https://bips.dev/340/).

Froglet's [kernel specification](/spec/kernel/) defines the exact artifact
bytes to sign; the [conformance vectors](/spec/conformance/) check interoperability.

## Identity in froglet

Your identity is your 32-byte x-only public key, encoded as a 64-character lowercase hex string:

```
Private key (secret, never shared):
  32 secret bytes in the valid key range

Public key / node_id (your identity):
  64 lowercase hexadecimal characters

Signature (64 bytes):
  128 lowercase hexadecimal characters
```

Signed protocol artifacts can be checked against the claimed public key.
The same key means the same signing identity, not necessarily the same person:
keys can be shared, delegated, or stolen. Protect the private key accordingly.

## Nostr linked identities

Froglet can link a separate **Nostr** publication key in its signed descriptor.
The descriptor and the Nostr event have their own signatures; verifiers check
the relationship between them. Publication makes this evidence discoverable,
but does not guarantee permanent storage. Relays can reject events or discard
older replaceable events under [Nostr's event rules](https://github.com/nostr-protocol/nips/blob/master/01.md).

:::tip[Key insight]
You can generate a signing identity locally. Signatures establish key control
and message integrity; real-world identity, service quality, and availability
need additional evidence.
:::
